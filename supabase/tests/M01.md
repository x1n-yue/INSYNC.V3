# M01 verification record and live test instructions

Local runner: `npm test -- tests/m01-authority.test.js`. Uses PGlite 0.5.8 (real
Postgres engine in memory), new synthetic fixtures and the actual M01 SQL. All
cases run under anon/authenticated roles with transaction-local synthetic auth.uid
claims; each case rolls back. No real endpoint, credentials or persistent data.
Phase 1 final full `npm test`: 3 files, 1,948 cases passed, including remaining
baseline probes and client transport tests. Build passed; lint zero errors/six
pre-existing warnings. Live checks below remain unexecuted.

The CRUD matrix has **1,716 cases**: 13 relations (12 tables + storage.objects) x
11 callers (3 roles x 3 statuses + anonymous + authenticated missing-profile) x
3 scopes x 4 operations. Reference-table ownership is N/A; intern assigned scope
coincides with own scope. Every role/status has actual owned domain/object rows;
denials are not inferred from missing fixture records. Domain ownership mutations,
privilege checks, RPC tampering, restricted names, signup metadata, retained identity,
review attribution and catalog checks supplement the matrix.

## Expected raw permissions after M01

Cell order SELECT / INSERT / UPDATE / DELETE. All require Active status. Admin
branches are explicit; RPC-only raw operations remain denied to Admin too.

|---|---|---|---|
| profiles | all / no / all protected management / no | self+assigned / no / self name / no | self / no / self name / no |
| interns | all / all / all / all | assigned / no / no / no | own / no / no / no |
| companies, course_sections, academic_years | all / all / all / all | all / no / no / no | all / no / no / no |

Non-Active profiles are not directly selectable; `my_profile()` returns only caller
id/status. Anonymous cannot execute app RPCs. Active interns get needed instructor/
evaluator names via `related_profile_names`, never the related staff's email/role/
student ID. Instructor `profiles!interns_id_fkey(full_name)` remains scoped and is
tested as an equivalent SQL join; PostgREST execution is pending.

## Mandatory disposable Supabase checks (NOT executed locally)

1. Compare before/after policies, table **and column** grants, routine owners/search
   paths/ACLs and trigger inventory. Assert no permissive old policy can OR-bypass
   M01. Check exposed schemas and pre-existing views/RPCs. Rerun catalog queries at
   the end of M01. API roles must not inherit postgres/BYPASSRLS or owner privileges.
2. Run the CRUD matrix via actual SDK/REST with fixture JWTs. On denial compare
   unchanged rows/objects, including zero-row UPDATE/DELETE. On success re-read
   committed state. Profile INSERT/DELETE intentionally unsupported; Auth signup
   owns creation. Test every protected field and both old/new ownership.
3. RT-01: missing/intern/instructor/admin/invalid/mixed-case effective role metadata,
   requested role and later edited metadata. Effective role always intern/Pending;
   profile+extension created together. Exercise confirmation on/off separately.
4. RT-02: ordinary self-name succeeds; role/status/id/email/student_id/organization/
   requested_role/created_at tampering fails. Admin approval works. Non-Active RPC
   returns only own id/status; unknown/missing profile cannot read data.
5. RT-03: distinct A/B rosters and unassigned C; reassignment transfers staff access
   but does not transfer announcement recipients. Direct INSERT/UPDATE to clocks,
   requests and review fields denied even with correct own UUID. Evaluator author
   bound; requirements Admin-only. Raw audit writes restricted but trusted audit
   generation is not implemented until M02.
6. Retain each JWT, deactivate account, repeat all business/Storage operations
   without refresh. Assert denied. React may show a stale dashboard until Phase 5
   focus/profile refresh; RLS must still deny its requests.
7. RT-04: private downloads/list/new upload across own/assigned/foreign, forged
   folders, object overwrite/rename/delete and bucket transfer. Assigned instructor
   cannot read an orphan or legacy path pointing to another intern's folder. Test
   **known-path anonymous delivery** separately: M01 cannot close a pre-existing
   public bucket; Phase 2 changes bucket configuration. Short-lived signed URL
   issuance/expiry tests also remain pending.
8. PostgREST: App `my_profile` JSON shape; every composite RPC shape; Instructor
   explicit intern-profile FK join and company join; Intern plain instructor UUID
   + restricted name RPC and evaluator-name mapping. No broad profile policy added
   merely to make an embedded join work.
9. Browser: legitimate name edit/Admin approval/assignment, clock/overnight correction,
   per-item and mixed bulk review, upload/reset/revision, duplicate-name recipient.
   Empty/error RPC responses must preserve drafts and never count as committed.

Limitations: Auth/Storage services and JWT cryptographic verification are mocked;
PGlite has one connection and does not prove two-client races/locks under production
load. HTTP signed URL delivery, browser and a11y remain unverified. New clock/review
RPCs already provide minimum server-derived intervals and atomic review as M01
prerequisites. Phase 2 still adds audit rollback/injection/concurrency tests, review
notes/bulk server outcomes, uniqueness/CHECKs after anomaly review and private bucket
limits. Phase 4 adds rubric validation and full document-version lifecycle. No
findings outside INS-001..008 are claimed complete by this phase.
